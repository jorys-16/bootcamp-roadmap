# How to Work Like a Master Developer

Habits matter more than talent. These are the practices to build during the 28 weeks.

## 1. Learn by building
Watching tutorials feels like progress but isn't. For every hour of reading or watching, spend two hours writing code. Finish small things rather than starting big things.

## 2. Read errors, don't fear them
- Read the whole error message, top to bottom, before touching the keyboard.
- Reproduce the bug in the smallest possible example.
- Change one thing at a time; if it doesn't fix it, revert.

## 3. Debug systematically
- Form a hypothesis ("the array is empty because the fetch failed"), then test it.
- Use a real debugger (VS Code breakpoints) instead of print statements when you can.
- Rubber-duck it: explain the code line by line out loud.

## 4. Ask questions well
Before asking: reproduce it, search the exact error, check the docs. When asking: show the code, the error, what you expected, and what you already tried.

## 5. Version control everything
Commit in small steps with messages that explain why, not what. Never debug without a commit to return to.

## 6. Space your practice
Two hours daily beats fourteen hours on Saturday. Review notes from last week before starting new material.

## 7. Write it down
If you can't explain a concept in your own words in `notes/`, you don't know it yet. Teach it to someone (tutoring counts).

## 8. Ship publicly
Deploy early, deploy often. A deployed ugly app teaches more than a perfect local one.

## 9. Measure honestly
Don't mark a week complete because time passed. Mark it complete when the deliverable exists and works.

## 10. Rest
Burnout costs more than any missed study session. Take the rest day.
